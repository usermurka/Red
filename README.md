# Красная книга Омской области — интерактивная карта {по состоянию на 31.10.26}

Веб-приложение для работы с данными Красной книги Омской области (2-е изд., 2015 г.):
интерактивная карта с маркерами местонахождений видов, областями обитания и линиями
миграций, справочник видов, полевой дневник наблюдений и набор обучающих мини-игр
с системой медалей (достижений).

Работает полностью в браузере без сервера и внешних зависимостей (vanilla JS + SVG).

## Возможности

### Карта
- 5 фоновых карт Омской области (переключатель «Вид карты»);
- панорамирование и масштабирование (мышью, тач-жестами и кнопками зума на мобильных);
- слои: маркеры местонахождений, области обитания (полигоны SVG), линии миграций;
- фильтр по категориям редкости (статусы 0–5 по классификации Красной книги) и по
  категориям объектов (животные, растения, лишайники, грибы);
- управляемые отображением элементы: области, миграции, бейджи редкости,
  иконки категории, маркеры;
- всплывающие подсказки по маркерам с быстрым редактированием/удалением;
- зона «поблизости» с настраиваемым радиусом (по умолчанию 10 км);
- статистика: всего видов в базе, отмечено видов, маркеров, областей.

### Режимы работы
- **Режим гостя** — просмотр карты, справочника и информации о видах;
- **Режим разработчика** — инструменты редактирования:
  - рисование областей обитания и линий миграций;
  - постановка маркеров, серийный режим (массовая простановка для одного вида);
  - скрытие/отображение объектов выбранного вида;
  - экспорт/импорт данных в JSON и GeoJSON, полная очистка.

### Справочник всех видов
Полный список видов Красной книги с карточками: название, латынь, статус редкости,
описание, фото (при наличии), таксономическая систематика.

### Полевой дневник наблюдений 📔
- добавление записей с привязкой к карте (несколько точек на запись, режим булавки);
- прикрепление фотографий (хранятся как data-URL внутри записей);
- автосохранение в `localStorage`, экспорт/импорт дневника JSON-файлом.

### Мини-игры и медали 🎮
Восемь игр по мотивам Красной книги:
| Игра | Описание |
|------|----------|
| 🎲 Викторина | вопросы о видах Красной книги |
| 🧩 Найди пару | сопоставление карточек |
| 🃏 Мемо | поиск пар изображений на память |
| 🦉 Эрудит | собери слово (название вида) |
| 🏛️ Латынь | соответствие русских и латинских названий |
| 🌍 Среда обитания | по фото и названию определи биом вида |
| 🎖️ Статус | по фото и описанию определи категорию редкости |
| 🗂️ Систематик | расложи карточки видов по таксономическим группам |

Общие правила новых механик («честная игра без подсказок из панели»):
- **Скрытая панель данных.** В играх «Среда обитания», «Статус» и «Викторина» боковая
  панель «Данные из Красной книги» скрыта до ответа игрока (класс
  `is-hidden` на теле панели переключает `setInfoVisible()` в
  `js/habitat.js` / `js/status.js`; вместо данных показывается заглушка
  `hp-locked-note`). Панель открывается после верного или неверного
  ответа, а также по истечении таймера — чтобы ответ можно было
  проверить по источнику. Оформление свитка — `js/mini-scroll.js`.
- **Подсветка биома.** После ответа в «Среде обитания» ключевые слова
  текста источника подсвечиваются (`mark.hl-forest/hl-steppe/hl-water/hl-bog`),
  а выбранный биом выделяется рамкой; подсветка скрывает/показывает
  связь ответа с формулировкой Красной книги.
- **Кнопка «Дальше» всегда видна.** Кнопка перехода между вопросами
  («Дальше →» / «Продолжить →») присутствует в DOM постоянно и занимает
  место, но до завершения вопроса бледная и неактивная (`is-idle`,
  `disabled`); после ответа/окончания раунда становится активной
  (`is-active`). Переход к следующему вопросу — только по явному нажатию.
- **Возврат карточек.** В игре «Систематик» карточки с неверным
  возвращением попадают обратно в лоток для повторной попытки.

Единая витрина медалей (достижения), кросс-игровые награды, счётчики сыгранных партий.
Прогресс хранится в `localStorage` и выгружается/загружается JSON-файлом
(кнопки «Сохранить» / «Загрузить»).

## Запуск

Приложение статическое — достаточно открыть `index.html` в браузере (данные
«зашиты» в `js/markers-data.js` и `js/species-data.js`, поэтому работает и по
`file://`), либо поднять любой локальный сервер:

```bash
# Python
python3 -m http.server 8000
```

Затем откройте http://localhost:8000

## Скрипты обслуживания

### Импорт видов (`scripts/import.py`)
```bash
cd scripts
py import.py           # обычный запуск
py import.py --force   # игнорировать защиту от повторного импорта
```
Логика одного цикла: читает `inbox/data.txt`, валидирует 18 полей (id, name, latin,
status и др.), проверяет id против `js/species.js`, защищает от дублирования
(id + хэш текста), добавляет/обновляет запись вида в `js/species-data.js`
(`SPECIES_DATA[id]`) и только после успеха переносит
картинку в `img/species/{id}.png`. Папка `inbox/` создаётся вручную — это очередь
видов для пакетного импорта. После каждого цикла — пауза (Enter — следующий
вид, Ctrl+C — выход).

### Генерация данных карты (`scripts/generate_markers_data.py`)
```bash
python3 scripts/generate_markers_data.py
```
Создаёт `js/markers-data.js` из `data/red-book-omsk.json`
(`window.MARKERS_DATA = { markers, regions, migrations }`) — «зашитые» данные
для работы приложения без сервера (file://). Запускайте после изменений в
`red-book-omsk.json`.

### Заполнение статусов (`scripts/fill_status_text.py`)
```bash
py fill_status_text.py
```
Обходит виды в порядке систематики `js/species.js` и предлагает вручную ввести
`status_text` для каждого (пишет в `js/species-data.js`). Управление: Enter с текстом — сохранить, пустой Enter —
пропустить, `u` — назад, `q` — выход (прогресс сохраняется).

## Хранение данных

Все пользовательские данные сохраняются в `localStorage` браузера:

| Ключ | Содержимое |
|------|-----------|
| `red_book_omsk_markers` | Маркеры местонахождений |
| `red_book_omsk_regions` | Области обитания (полигоны) |
| `red_book_omsk_migrations` | Линии миграций |
| `red_book_journal` | Записи полевого дневника (фото — data-URL внутри записей) |
| `red_book_games_progress_v1` | Прогресс и медали мини-игр |

Для переноса между устройствами используйте кнопки «Экспорт JSON / GeoJSON» и
«Импорт» на панели, а для игр — «Сохранить / Загрузить» в режиме «Игры».

## Технологии

- HTML5 / CSS3 / JavaScript (ES6+), без фреймворков, сборщиков и npm-зависимостей;
- Ядро приложения разбито на модули `js/app-*.js`, каждый из которых дополняет
  единый объект `window.App` через `Object.assign`. Загружаются обычными
  тегами `<script defer>` в фиксированном порядке: `core → ui → map → regions →
  species → render → tooltips → guide` (в `guide` вызывается `App.init()`).
  Порядок важен, ES-модули (`import/export`) не используются;
- SVG-слой для полигонов областей и линий миграций;
- Canvas-free рендеринг маркеров через DOM;
- Python 3 — вспомогательные скрипты импорта/валидации данных.
