# Красная книга Омской области — интерактивная карта

**Версия: v.11.02** (по состоянию на 02.11.2026)

Веб-приложение для работы с данными Красной книги Омской области (2-е изд., 2015 г.):
интерактивная карта с маркерами местонахождений видов, областями обитания и линиями
миграций, справочник видов, полевой дневник наблюдений и набор обучающих мини-игр
с системой медалей (достижений).

Работает полностью в браузере без сервера и внешних зависимостей (vanilla JS + SVG).

## Возможности

### Карта
- 5 фоновых карт Омской области (переключатель «Вид карты»);
- панорамирование и масштабирование (мышью; на мобильных/планшетах — щипок,
  кнопки ＋/－ скрыты, осталась только кнопка ⟳ «вернуть карту на весь экран»,
  оформленная как кнопка ☰ и расположенная симметрично ей);
- слои: маркеры местонахождений, области обитания (полигоны SVG), линии миграций;
- фильтр по категориям редкости (статусы 0–5 по классификации Красной книги) и по
  категориям объектов (животные, растения, лишайники, грибы);
- управляемые отображением элементы: области, миграции, бейджи редкости,
  иконки категории, маркеры;
- всплывающие подсказки по маркерам с быстрым редактированием/удалением;
- зона «поблизости» с настраиваемым радиусом (по умолчанию 10 км);
- статистика: всего видов в базе, отмечено видов, маркеров, областей.

### Режимы работы
- **Режим гостя** — просмотр карты, справочника и информации о видах;
- **Режим разработчика** — инструменты редактирования:
  - рисование областей обитания и линий миграций;
  - постановка маркеров, серийный режим (массовая простановка для одного вида);
  - скрытие/отображение объектов выбранного вида;
  - экспорт/импорт данных в JSON и GeoJSON, полная очистка.

### Справочник всех видов
Полный список видов Красной книги с карточками: название, латынь, статус редкости,
описание, фото (при наличии), таксономическая систематика.

### Полевой дневник наблюдений 📔
- добавление записей с привязкой к карте (несколько точек на запись, режим булавки);
- прикрепление фотографий (хранятся как data-URL внутри записей);
- автосохранение в `localStorage`, экспорт/импорт дневника JSON-файлом;
- **мобильно-планшетная компоновка (≤1024px):** записи идут первыми (вверху) без
  внутреннего скролла («без лифта»); карта скрыта и открывается отдельным
  полноэкранным окном по кнопке «🗺» в карточке записи — метки открытой
  карточки подсвечены золотым ореолом; возврат из окна карты — круглой
  кнопкой «⟵» (стиль ☰), закрытие окна — также тапом в фон; кнопки ＋/－
  в окне карты не показываются; панель «📍 Поставить метку / 🗺 Открыть
  карту» лежит над списком записей; при открытом дневнике кнопки ⟳ и ☰
  скрыты, возврат в исходное состояние — фиксированным ✕ в правом верхнем
  углу (шапка с кнопками «Сохранить/Загрузить» имеет отступы, чтобы они
  не залезали под ✕); кнопка «📔 Дневник» в меню подсвечивается, пока
  дневник открыт. На десктопе (>1024px) значок «🗺» в карточках скрыт —
  карта видна рядом со списком.

### Автооткрытие справочника видов
Справочник автоматически открывается при настройке фильтров боковой панели
(слои, статусы) **только на десктопе** (>1024px). На планшетах и мобильных
устройствах автоотключение заблокировано: фильтры применяются к карте, но
полноэкранная шторка справочника не перекрывает её. Явные действия
(лупа в тултипе, кнопки «➕ Добавить вид», «Список видов») открывают
справочник как раньше.

### Мини-игры и медали 🎮
Восемь игр по мотивам Красной книги:
| Игра | Описание |
|------|----------|
| 🎲 Викторина | вопросы о видах Красной книги |
| 🧩 Найди пару | сопоставление карточек |
| 🃏 Мемо | поиск пар изображений на память |
| 🦉 Эрудит | собери слово (название вида) |
| 🏛️ Латынь | соответствие русских и латинских названий |
| 🌍 Среда обитания | по фото и названию определи биом вида |
| 🎖️ Статус | по фото и описанию определи категорию редкости |
| 🗂️ Систематик | расложи карточки видов по таксономическим группам |

Общие правила новых механик («честная игра без подсказок из панели»):
- **Скрытая панель данных.** В играх «Среда обитания», «Статус» и «Викторина» боковая
  панель «Данные из Красной книги» скрыта до ответа игрока (класс
  `is-hidden` на теле панели переключает `setInfoVisible()` в
  `js/habitat.js` / `js/status.js`; вместо данных показывается заглушка
  `hp-locked-note`). Панель открывается после верного или неверного
  ответа, а также по истечении таймера — чтобы ответ можно было
  проверить по источнику. Оформление свитка — `js/mini-scroll.js`.
- **Подсветка биома.** После ответа в «Среде обитания» ключевые слова
  текста источника подсвечиваются (`mark.hl-forest/hl-steppe/hl-water/hl-bog`),
  а выбранный биом выделяется рамкой; подсветка скрывает/показывает
  связь ответа с формулировкой Красной книги.
- **Кнопка «Дальше» появляется только после ответа.** В «Викторине» кнопка перехода
  между вопросами до ответа полностью скрыта (`display:none`, класс `hidden`) —
  неактивная «бледная» кнопка в окне не занимает место. После угадывания (или
  истечения таймера) появляется новая активная кнопка: «Следующий вопрос →»,
  на последнем вопросе — «Показать результаты 🏆». Переход — только по явному
  нажатию. В остальных играх («Эрудит», «Статус» и др.) используется прежняя
  схема с неактивной кнопкой (`is-idle`).
- **Возврат карточек.** В игре «Систематик» карточки с неверным
  возвращением попадают обратно в лоток для повторной попытки.

### Мобильно-планшетные исправления v.11.02 (02.11.2026)

**Игры:**
- **«Систематик», «Статус», «Латынь» — щель под шапкой.** Убран внутренний
  скролл игрового окна с sticky-шапкой: теперь вся колонка модалки
  прокручивается целиком (как в «Эрудите»/«Мемо»), данные поля больше не
  просвечивают в зазор между фиксированным верхом и шапкой. Кнопки ↺/✕
  закреплены (`position:fixed`) и не уезжают при прокрутке.
- **«Среда обитания» — свиток.** Окно сделано полноэкранным с корректной
  прокруткой: при свёрнутом мини-свитке контент целиком виден без скролла,
  при раскрытом — прокручивается внутри окна, верх игры (шапка, таймер)
  не обрезается. Длинные названия видов в журнале пар переносятся
  (`overflow-wrap:anywhere`), а не вылезают за границы колонок.
- **«Латынь» — рубашки карточек.** Надпись «КРАСНАЯ КНИГА» уменьшена до
  размера относительно самой карточки (`clamp(8px, 13cqi, 12px)` через
  container query + `font-size:11px` на узких экранах); раньше на мобильных
  она была слишком крупной и распирала рубашку.
- **«Найди пару» — сетка 4×5.** На мобильных 20 карточек раскладываются
  4 колонки × 5 рядов вместо 5×4; карточки квадратные, домино-анимация и
  зум не затронуты. Подложка окна на планшетах растянута по содержимому
  (`width:auto`), карточки больше не вылезают за её край. Десктоп остаётся 5×4.
- **«Систематик» — тап вместо перетаскивания.** На тач-устройствах
  HTML-drag отключён (`draggable=false` при `pointer:coarse`): тап по
  карточке лотка выделяет её и подсвечивает корзины (класс `fb-await`),
  тап по корзине кладёт вид, тап по строке в корзине возвращает её в
  лоток. Добавлены `touch-action:manipulation` и отмена нативного drag
  картинок.
- **«Статус» — сворачиваемый блок.** В мини-свитке «Численность и
  лимитирующие факторы» свёрнут в `<details>` с раскрытием по тапу —
  аналогично «Распространению в Омской области» в «Среде обитания».

**Карта:**
- На мобильно-планшетной версии убраны кнопки ＋/－ — достаточно щипка;
  третья кнопка (вернуть карту на весь экран) заменена на круглую стрелку
  ⟳ («как обновление») и оформлена идентично кнопке вызова меню ☰
  (круг 46px, тот же градиент/рамка/тень), расположена симметрично ☰ на
  той же высоте.

**Полевой дневник (≤1024px):**
- Компановка «записи сверху»: список идёт первым, без ограничения высоты
  («без лифта»); карта скрыта из потока.
- Клик по карточке записи РАЗВОРАЧИВАЕТ её; отдельная кнопка «🗺 Открыть
  карту» открывает полноэкранное окно карты с метками этой записи; метки
  соответствующие карточке отличаются золотым ореолом (`.journal-marker.from-card`).
- Кнопка «📍 Поставить метку» (и «🗺 Открыть карту») вынесена в панель над
  карточками записей, а не внутрь окна карты; режим меток синхронизирован
  с оригинальной кнопкой.
- При открытом дневнике кнопки ⟳ и ☰ скрыты; возврат в исходное состояние —
  единый маленький аккуратный ✕ (26px, круглый). Он стоит В ОДНОЙ СТРОКЕ с
  заголовком «📔 Полевой дневник» и кнопками «💾 Сохранить» / «📂 Загрузить»:
  перенос строк запрещён (`flex-wrap:nowrap`), при нехватке места заголовок
  усекается многоточием, а кнопки сжимаются до текста. Поворот ✕ на 90° из
  style.css отключён (залипший тач-hover рисовал «огромный овал»). Второй
  (дублирующий) крестик удалён из разметки и принудительно скрыт CSS —
  на десктопе тоже виден только один ✕.
- Кнопка «🗺 Открыть карту» есть только в мобильно-планшетной версии: JS не
  рендерит её на десктопе (>1024px), плюс CSS-страховка `display:none`.
- Форма «Описать вид» открывается поверх окна карты (z-index 2600) —
  раньше была невидима.
- Кнопка «⟵» возврата из окна карты вынесена в `<body>` (`position:fixed`,
  z-index 2510) — клик по ней гарантированно работает; закрытие также по
  тапу в фон оверлея.
- Кнопка «📔 Дневник» в меню получает подсветку `.active`, пока дневник
  открыт; повторный клик закрывает дневник.
- Десктоп (>1024px): значок «🗺» в карточках скрыт, компоновка «карта слева
  — список справа» без изменений.

### Мобильные исправления v.11.01

- **Скролл витрины медалей.** В режиме «Игры» окно медалей (`#games-showcase`)
  скроллится тачем на узких экранах: витрина жёстко растянута на всю высоту
  контейнера карты (`position:absolute; inset:0; height:100%; overflow-y:scroll`),
  тач-обработчики панорамирования карты пропускают свайпы по витрине, а в
  `js/app-map.js` добавлен фолбэк ручной прокрутки на случай, если браузер не
  выполнит нативный скролл.
- **«Эрудит» — картинка и интерфейс.** Фото вида больше не схлопывается в строку
  (`aspect-ratio:1/1`, `min-height` у `<img>` в `css/erudite.css`). Устранён
  `TypeError` (`this.letters.replace(...)` вызывался на массиве букв), который
  обрывал сборку раунда на однословных названиях — из-за него картинка была,
  а лоток букв и слоты оставались пустыми. Сборка раунда защищена `try/catch`,
  пересчёт размеров выполняется через двойной `requestAnimationFrame`. Та же
  ошибка устранена в подсказке «Перемешать».
- **«Латынь», «Статус», «Систематик» — шапка и кнопки.** На мобильных окнах
  отключён `clip-path` (обрезал шапку), кнопки ↺/✕ прижаты к видимому углу
  окна (`position:fixed` в `css/responsive.css`), шапка с названием игры —
  липкая (`position:sticky; top:0`), верхняя граница с управлением больше
  не уходит за экран.

Единая витрина медалей (достижения), кросс-игровые награды, счётчики сыгранных партий.
Прогресс хранится в `localStorage` и выгружается/загружается JSON-файлом
(кнопки «Сохранить» / «Загрузить»).

## Деплой (GitHub Pages)

Статический хостинг через GitHub Pages, workflow `.github/workflows/pages.yml`
(`actions/deploy-pages` v5). В workflow настроен блок `concurrency` с
`cancel-in-progress: true` — новый пуш автоматически отменяет зависшее
предыдущее развертывание, что исключает ошибку «не удалось создать
развертывание из-за незавершенного развертывания» (HTTP 400). Требуется
настройка источника сборки Pages = «GitHub Actions» в настройках репозитория.

## Запуск

Приложение статическое — достаточно открыть `index.html` в браузере (данные
«зашиты» в `js/markers-data.js` и `js/species-data.js`, поэтому работает и по
`file://`), либо поднять любой локальный сервер:

```bash
# Python
python3 -m http.server 8000
```

Затем откройте http://localhost:8000

## Скрипты обслуживания

### Импорт видов (`scripts/import.py`)
```bash
cd scripts
py import.py           # обычный запуск
py import.py --force   # игнорировать защиту от повторного импорта
```
Логика одного цикла: читает `inbox/data.txt`, валидирует 18 полей (id, name, latin,
status и др.), проверяет id против `js/species.js`, защищает от дублирования
(id + хэш текста), добавляет/обновляет запись вида в `js/species-data.js`
(`SPECIES_DATA[id]`) и только после успеха переносит
картинку в `img/species/{id}.png`. Папка `inbox/` создаётся вручную — это очередь
видов для пакетного импорта. После каждого цикла — пауза (Enter — следующий
вид, Ctrl+C — выход).

### Генерация данных карты (`scripts/generate_markers_data.py`)
```bash
python3 scripts/generate_markers_data.py
```
Создаёт `js/markers-data.js` из `data/red-book-omsk.json`
(`window.MARKERS_DATA = { markers, regions, migrations }`) — «зашитые» данные
для работы приложения без сервера (file://). Запускайте после изменений в
`red-book-omsk.json`.

### Заполнение статусов (`scripts/fill_status_text.py`)
```bash
py fill_status_text.py
```
Обходит виды в порядке систематики `js/species.js` и предлагает вручную ввести
`status_text` для каждого (пишет в `js/species-data.js`). Управление: Enter с текстом — сохранить, пустой Enter —
пропустить, `u` — назад, `q` — выход (прогресс сохраняется).

## Хранение данных

Все пользовательские данные сохраняются в `localStorage` браузера:

| Ключ | Содержимое |
|------|-----------|
| `red_book_omsk_markers` | Маркеры местонахождений |
| `red_book_omsk_regions` | Области обитания (полигоны) |
| `red_book_omsk_migrations` | Линии миграций |
| `red_book_journal` | Записи полевого дневника (фото — data-URL внутри записей) |
| `red_book_games_progress_v1` | Прогресс и медали мини-игр |

Для переноса между устройствами используйте кнопки «Экспорт JSON / GeoJSON» и
«Импорт» на панели, а для игр — «Сохранить / Загрузить» в режиме «Игры».

## Технологии

- HTML5 / CSS3 / JavaScript (ES6+), без фреймворков, сборщиков и npm-зависимостей;
- Ядро приложения разбито на модули `js/app-*.js`, каждый из которых дополняет
  единый объект `window.App` через `Object.assign`. Загружаются обычными
  тегами `<script defer>` в фиксированном порядке: `core → ui → map → regions →
  species → render → tooltips → guide` (в `guide` вызывается `App.init()`).
  Порядок важен, ES-модули (`import/export`) не используются;
- SVG-слой для полигонов областей и линий миграций;
- Canvas-free рендеринг маркеров через DOM;
- Python 3 — вспомогательные скрипты импорта/валидации данных.
