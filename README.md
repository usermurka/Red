# Карта видов — Омская область

Интерактивная карта наблюдений редких видов растений и животных с журналом полевых
наблюдений, справочником видов, областями обитания, линиями миграций и мини-играми
(викторина, «мемори», «найди пару», «эрудит»). Чистый HTML/CSS/JS, без сборки — статический
сайт, работает от любого локального сервера (`python -m http.server`) или напрямую
с GitHub Pages.

## Структура

```
index.html          — главная страница (карта + панель управления)
css/style.css       — основные стили; quiz.css, match.css, memo.css, erudite.css — стили игр
js/app.js           — основная логика карты, маркеров, тултипов, зума/пана
js/journal.js       — журнал полевых наблюдений (импорт/экспорт JSON)
js/config.js        — конфигурация: категории, статусы, форматы маркеров, хэш пароля деврежима
js/storage.js       — сохранение маркеров/областей/миграций в localStorage
js/species*.js      — справочник видов и загрузчик данных
js/quiz.js/match.js/memo.js/erudite.js — мини-игры
data/, img/, inbox/ — данные видов, изображения, входящие файлы импорта
import.py, merge.html, scripts/ — вспомогательные скрипты подготовки данных (не часть рантайма)
```

# Что проверять в ветке фикса (чек-лист для тестировщиков)

В ветке выполнены: **исправления безопасности (XSS, пароль деврежима, валидация
импорта)** и **оптимизация производительности (рендер карты, поиск, загрузка
страницы)**. Также исправлено поведение маркеров при панорамировании.

## 1. КАРТА: маркеры, пан и зум (главная правка этой итерации)

Маркеры и SVG-слой областей лежат ВНУТРИ `#map-wrapper` и трансформируются
строго вместе с картой одним CSS-transform'ом wrapper'а — никаких
дополнительных контр-масштабов слоёв и покадровых пересчётов в JS.

- [ ] **Пан (перетаскивание мышью)**: маркеры, области и линии миграций движутся
      строго синхронно с картой — БЕЗ отставания/«догоняния» и дрожания.
- [ ] **Пан тачем (один палец)** — то же самое на мобильном.
- [ ] **Зум колесом к курсору**: маркеры остаются привязанными к своим точкам
      карты и масштабируются вместе с ней (как исходное поведение); точка под
      курсором не «уползает».
- [ ] **Pinch-зум двумя пальцами** на мобильном: полная синхронность маркеров
      с картой при изменении масштаба.
- [ ] **Кнопки ＋ / － / ⤢** (мобильная панель): корректный зум, сброс к x1;
      после сброса маркеры стоят на своих местах.
- [ ] **Hover на маркере**: увеличение работает на любом уровне зума.
- [ ] **Подсветка «мигания»** (клик по виду в списке → flashMarkers): пульс
      работает, жёлтая обводка видна при зуме > 1.
- [ ] **Клик по маркеру при сильном зуме**: тултип открывается рядом с кликом,
      не «гуляет» (тултип лежит вне wrapper'а — его позиция не зависит от пана).
- [ ] **Перетаскивание тултипа** за заголовок — работает как раньше.
- [ ] **Рисование областей/миграций** при зуме ≠ 1: точки рисуются точно под
      курсором; после сохранения полигон/линия стоят на своих местах при
      любом пан/зуме.
- [ ] **Resize окна / поворот мобильного**: позиции маркеров пересчитываются
      корректно (метод updateMarkerPositions вызывается только на реальные
      изменения размеров).
- [ ] **Смена подложки карты** (если доступен переключатель слоёв): маркеры и
      области остаются привязанными к географии.

## 1a. ИМПОРТ ДАННЫХ (red-book-omsk.json) — новое поведение

Загруженные из файла данные НЕ выделяются и НЕ показываются автоматически.

- [ ] **Импорт через «Импорт» → red-book-omsk.json**: после загрузки карта
      чистая — ни одного маркера, области или линии миграции НЕ видно
      (подсветка видов очищена, режим «только выбранные» активен).
- [ ] Данные при этом **сохранены**: выбрать вид в справочнике/фильтре →
      его маркеры, области и линии сразу появляются на карте.
- [ ] **Экспорт → импорт → повторный экспорт**: содержимое файла не изменилось
      (данные не потерялись из-за скрытия).
- [ ] Импорт **старого формата** (простой массив маркеров) — тоже без
      автопоказа, но маркеры доступны через фильтры.
- [ ] Импорт **битого JSON** — понятная ошибка, старые данные целы.

## 2. Безопасность

- [ ] **XSS через название маркера/комментарий**: создать маркер с именем вида
      `<img src=x onerror=alert(1)>` или `<script>alert(1)</script>` — в
      тултипе, списке и редакторе текст должен отображаться БУКВАЛЬНО,
      никакого выполнения кода и поломки вёрстки.
- [ ] **XSS через импорт журнала**: в JSON-файле импорта подставить вредоносные
      строки в поля name/comment — после импорта всё экранировано.
- [ ] **Импорт битого JSON / чужого файла**: понятная ошибка, приложение не
      падает, старые данные не теряются. Проверяется структура данных до
      записи в localStorage.
- [ ] **Режим разработчика**: пароль больше не хранится в открытом виде
      (только SHA-256 хэш в config.js). Старый пароль НЕ подходит; ввод
      правильного пароля включает деврежим (проверить у владельца значение).
      Проверка работает только на https или localhost (crypto.subtle).
- [ ] **Данные в URL/hash** (если использовались deep-links) — не приводят к
      выполнению скриптов.

## 3. Производительность

- [ ] **Пан при 300+ маркерах**: 55–60 fps, нет просадок (в DevTools →
      Performance запись drag-теста: transform меняется только на wrapper'е).
- [ ] **Зум колесом подряд x10**: без «залипания» — единственный transform
      меняется только на wrapper'е, слои маркеров/областей не пересчитываются.
- [ ] **Поиск в справочнике**: быстрый набор текста без лагов (результаты
      кэшируются, пересчёт только по изменению запроса).
- [ ] **Загрузка страницы**: скрипты грузятся с `defer`, контент виден до
      инициализации App; Lighthouse Performance ≥ предыдущей версии.
- [ ] **Память**: многократное открытие/закрытие тултипов и модалок не
      увеличивает число слушателей (нет утечек — проверить в DevTools
      Memory → event listeners count стабилен).

## 4. Регрессия основного функционала

- [ ] Постановка маркера (обычный и серийный режим), редактирование, удаление.
- [ ] Фильтры по категориям/статусам, «На карте только выбранные».
- [ ] Справочник: дерево/алфавит, выбор вида → подсветка маркеров и областей.
- [ ] Журнал: добавление записи, экспорт → импорт на другой машине — данные
      сохраняются полностью.
- [ ] Мини-игры (quiz/match/memo) запускаются, работают после закрытия модальных окон.
- [ ] Мобильная вёрстка: шторка панели, кнопки зума, тапы без ложных
      постановок маркеров после свайпа.

## 5. Новая игра «Эрудит» (собери слово) — что проверять

Кнопка 🦉 «Эрудит» в меню игр. По картинке вида нужно собрать его название из
перемешанных букв (клик по плитке буквы → буква встаёт в следующий слот;
автопроверка при заполнении всех слотов). 5 раундов, очки и серия побед.

- [ ] Игра открывается/закрывается (✕), кнопка ↺ начинает заново; после закрытия
      карта и остальные кнопки работают (pointerEvents восстанавливается).
- [ ] Название вида НЕ показывается до проверки слова (в alt картинки тоже).
- [ ] Клик по букве ставит её в слот, повторный клик недоступен (плитка гаснет);
      ⌫ убирает последнюю букву, 🔀 перемешивает оставшиеся, ⏭ пропускает слово.
- [ ] Верное слово → зелёные слоты, +очки, серия растёт; неверное → красные
      слоты с анимацией, показ правильного слова, серия сбрасывается.
- [ ] Клавиатура (desktop): русские буквы расставляют плитки, Backspace откатывает,
      Enter проверяет; ввод латиницы/символов игнорируется.
- [ ] Экран итогов: корректные счётчики (собрано/всего, лучшая серия) и выдача
      достижений; «Играть снова» перезапускает без накопления слушателей.
- [ ] Слова берутся только длиной 4–12 букв (без пробелов/дефисов) — длинные
      названия не должны попадать в раунды; при нехватке видов — аккуратный alert.
- [ ] Если у вида нет картинки — placeholder, игра не ломается.
- [ ] XSS: пользовательский вид с названием вроде `<img src=x onerror=alert(1)>`
      не приводит к выполнению кода (вывод названий идёт через textContent).
- [ ] Мобильные экраны ≤520px: слоты/плитки уменьшены, всё влезает, тапы точные.

## Известные ограничения

- Пароль деврежима задаётся через генерацию SHA-256 хэша (инструкция в
  комментарии `js/config.js`). На `http://` (не localhost) `crypto.subtle`
  недоступен — вход в деврежим там работать не будет (это осознанно).
- При очень большом числе (>1000) одновременно видимых маркеров полный
  перерисовка render() остаётся самой дорогой операцией; она вызывается
  только при реальном изменении набора маркеров/фильтров.
